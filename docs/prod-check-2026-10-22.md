## Classification

Hippocampus has no payments, but it holds one person's entire memory store: identity, projects, people, decisions, daily logs. It also runs a real login: an OAuth 2.1 authorization server with a password form and token issuance, plus static agent tokens. "Customer data" plus "user accounts" puts it at T1 even with a single user. T2 does not apply: there is no regulated data class and no contract terms. Multi-tenant is off, because there is one owner and no shared-workspace entity. AI/LLM is off: embeddings run locally (all-MiniLM-L6-v2), and no model can call tools on the server's side. The MCP tools are called *by* AI clients and authenticated like any other API.

The stage column is copied from the check files. Strictly, `launch` (first user outside the team, or first invoice) has not happened; the rows are treated as due now **by choice**, because the instance already holds real data that every briefing and agent depends on.

## Summary

Twelve FAILs and seven UNKNOWN (four for want of console or registrar access, two attestations, one with no artifact). Two findings carry most of the risk:

1. **The login form has no throttle.** `POST /authorize` has no rate limit (the only limiter is mounted on `/mcp`), so an attacker can guess the one password online, without limit, against the form that issues a 30-day refresh token. The password is also checked against an unsalted SHA-256, though on this box that matters less (see AUTH-09).
2. **The database has no backup.** Nothing on the box, in the repo or on the laptop copies `hippocampus.db`, and no restore has ever been done (`SECURITY.md` lists both as unchecked). Combined with SEC-06 (every agent token can call `forget` and `merge`), one leaked token or one bad volume means total loss.

The reviewer also found that the public docs promise controls the code does not have: `README.md` says "Rate limiting on all endpoints", and `SECURITY.md` §"Rate limiting" lists per-endpoint limits, a 10 KB body cap and an observation cap. None of these exist, and `RATE_LIMIT_REMEMBER` is parsed but never read (`src/config.ts`). A self-hoster reading `SECURITY.md` would believe AUTH-05 and WEB-01 are handled. The fixes below correct the docs in the same change.

## Other observations (outside the quick IDs)

- **The open-registration token phish on `/authorize`** is still open and already tracked (ROADMAP → Next, D24). With AUTH-05 and AUTH-09 also fixed, the login form would be guarded on all three axes.
- **Fail-open default for self-hosters.** `bearerAuth()` lets every request through when neither `HIPPO_OAUTH_ISSUER` nor `HIPPO_TOKEN` is set (`if (config.token) {...} return next()`). This instance is not affected (OAuth is configured, and unauthenticated `/mcp` returns 401). A self-hoster who skips both variables gets an open memory server with no warning. Not a quick-profile row; worth a refuse-to-start or a loud startup warning.
- **No container memory limit** (`mem=0` on the running container; SRV-10 is outside the quick list). The July OOM (CLAUDE.md) took the process to about 1.9 GB of heap on a 3.8 GB box shared with other services.
- **`SECURITY.md` has no vulnerability-reporting contact** for the open-source project.

## Method and deviations

- All box reads were status commands over ssh: `ss`, `ufw status`, `sshd -T`, `systemctl`, `docker compose ps`, env **names** from the compose env file via `cut -d= -f1`, `docker system df`. No service was restarted, and no config, firewall or database was changed.
- **Two commands went beyond pure reads, and both were avoidable.** (1) Listing the data volume, I ran a throwaway `busybox` container with the volume mounted read-only. It pulled the `busybox` image onto the box, which is still there (about 4 MB). Removing it is a write, so it waits for the owner's OK. (2) The SQLite version came from `docker exec hippocampus node -e ...`, which opens an in-memory database only, though the same version is readable from the lockfile without touching the box.
- `docker compose config --format json | jq` failed because `jq` is not installed on the box, and the plain form (which prints values) was deliberately not run. Env names came from the env file instead.
- Nothing was burst-tested or replayed against production. There is no test environment, so the auth and authz rows are code-read and marked "(code only)".
